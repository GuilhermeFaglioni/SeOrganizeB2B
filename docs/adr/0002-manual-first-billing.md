# Cobrança manual-primeiro, sem gateway de pagamento

A primeira versão da cobrança ao cliente final é manual/leve: gerar invoice/PDF com PIX copia-e-cola (chave estática do prestador + valor) e lembrete de vencimento via push/in-app, mantendo o "marcar pago" manual que o módulo financeiro já tem. E-mail fica para uma fase posterior (não há provedor de e-mail configurado hoje — `sendInviteEmail` é stub), quando o provedor + agendador forem escolhidos. Não há integração com PSP (Asaas, Mercado Pago, Stripe etc.) nem webhook de pagamento nesta fase — a automação fica como passo posterior. Motivo: destravar o valor de "cobrar + lembrar" sem dependência externa nem o risco de webhooks/reconciliação, e sem contradizer a spec atual do financeiro ("no payment-gateway integrations").
