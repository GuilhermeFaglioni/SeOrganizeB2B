# Cobrança manual-primeiro, sem gateway de pagamento

A primeira versão da cobrança ao cliente final é manual/leve: gerar invoice/PDF com PIX copia-e-cola (chave estática do prestador + valor) e lembrete de vencimento via push/in-app, mantendo o "marcar pago" manual que o módulo financeiro já tem. Email de cobrança continua reservado para uma fase posterior, quando houver provedor + agendador específicos. Convites de colaboradores ficam pendentes e são vinculados por email normalizado mais um código manual definido pelo admin do workspace; nenhum email de convite é enviado nesta fase. Não há integração com PSP (Asaas, Mercado Pago, Stripe etc.) nem webhook de pagamento nesta fase — a automação fica como passo posterior. Motivo: destravar o valor de "cobrar + lembrar" sem dependência externa nem o risco de webhooks/reconciliação, e sem contradizer a spec atual do financeiro ("no payment-gateway integrations").
